> **总纲（不可违背的五条架构铁律）**
> A1. **规则与判定只能由确定性规则引擎执行**；LLM 仅用于证据采集、非结构化数据结构化与定性初评，其输出落库为带来源证据对象后，由规则引擎判定。代理输出中的判定性语言仅存档参考，判定字段一律由规则引擎重算覆盖。
> A2. **无数据不出结论**：计算节点缺输入时输出"缺口对象"，按框架条款降级（计低档/不推荐/滞留），禁止插值补齐。**显式签署例外**：指引兑现率冷启动期按中档下限计（O-01 决策 2 签署口径）。
> A3. **系统无交易执行权**：不集成下单接口；输出止于意见对象。
> A4. **一切输出可回溯**：判定 → 规则条目 ID + 快照 ID + 证据对象 ID 三元组，全链 append-only。
> A5. **防守类动作永不被冻结阻断**：6.6 顺位前三级（红线处置、证伪清仓、止损减半）与回撤阶梯动作不受任何冻结标志位约束，此为与红线同级的不可配置断言。〔校验 C-01 修订〕

## 1. 概述

### 1.1 系统定位
框架 v2.0 的软件实现：月度自动执行"行业闸门 → 候选扫描 → 一票否决 → 八维评分 → 三情景 → 风控校验 → 推荐清单与七类意见"管道；信号触发的持仓实时监测与复评；用户签认/裁决闭环；全程存证；季度意见质量校准。

### 1.2 范围
范围内：D1-D10 数据采集与质量控制、规则库与参数管理、四层流程编排、全部分析引擎（含持仓信号监测与论点卡证伪状态机）、LLM 取证代理子系统、签认/裁决工作流、存证审计、质量校准。范围外：交易执行；收益预测；框架外任何策略。

### 1.3 名词表
| 术语 | 定义 |
|---|---|
| 规则条目 | 框架条文的机器可执行表示（出处/参数/触发/动作/效力级/保守方向） |
| 证据对象 | 带来源（source_id）、日期、口径、新鲜度、置信标签的结构化数据点 |
| 缺口对象 | 显式数据缺失记录（字段、尝试路径、降级动作） |
| 意见对象 | 框架第十章七类之一，含 10.2 十项必备字段 |
| 裁决 | 用户对边缘/冲突项的书面决定。已发生：裁决 A；**待决请求**：D-1~D-3（S3 第 1 期提出，尚未裁决）〔校验 B-08 修订〕 |

| 观察期 | 6.2 复评"不能确认红旗"后的减半观察状态（一个季度，期内再命中任一信号直接清仓）〔框架 6.2〕 |
| 候选分组 | A 组=全数据口径可得（进 S3）；B 组=非美披露源未接入（缓评）；C 组=A 股待数据通道（缓评）〔沿用 S2 第 1 期口径，校验 B-09〕 |
