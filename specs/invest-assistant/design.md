# 智能投资助手 — 技术设计文档（design）

> 上游：`requirements.md`（R1-R20）←《智能投资助手-软件规格书 v1.1》←《AI时代股票投资指导框架 v2.0》。冲突时效力顺位：框架 v2.0 > 设计方案 v2.0 > 规格书 v1.1 > 本设计文档。
> 本文档回答"怎么实现"；业务阈值一律不在此复写数值，只引用规则条目 ID（防止双源漂移，见 §3.2）。

## 1. 概览与设计原则

系统是框架 v2.0 的确定性执行器：月度管道（S1→S5）+ 事件驱动复评（S10/S11）+ 签认/裁决人机闭环 + 全链存证。五条架构铁律（A1-A5）不是功能需求而是**横切不变量**，落法如下：

| 铁律 | 落法（设计机制） |
|---|---|
| A1 判定仅规则引擎 | 判定字段只能由 `RuleEngine.evaluate()` 写入；evidence 表 `置信` 字段由校验器置位，ORM 层拒绝代理/人工直写；代理输出的判定性语言进 `agent_opinion_ref` 参考字段，不参与运算 |
| A2 无数据不出结论 | 计算节点输入用 `Either[Gap, Value]` 类型建模：任何节点收到 Gap 只能向下传播 Gap 或执行规则库登记的降级动作，类型系统层面无法插值（唯一签署例外：R2.8 冷启动） |
| A3 无交易执行权 | 依赖白名单：代码库禁止引入下单类 SDK；IBKR 适配器仅实现行情/图谱/日历读取接口，CI 静态检查拒绝 order/place/submit 类调用 |
| A4 全链可回溯 | 一切判定产物强制外键三元组（rule_id, snapshot_id, evidence_ids[]），数据库 NOT NULL 约束 + 写入时校验证据 ID 存在于所引快照 |
| A5 防守动作不被冻结 | 冻结检查器实现为纯函数 `freeze_gate(action_class, freeze_flags) -> Allow/Deny`，其中 `action_class == DEFENSIVE → Allow` 为第一条短路分支，写死在代码（红线断言层，FR-R-01 允许的唯一硬编码位置），并有专门回归用例（R20.5） |

## 2. 架构

### 2.1 分层视图（L0-L7 + 代理旁路）

```
 L7 交互层      签认队列 | 裁决队列 | 报告/意见展示 | 强送达通知           (R17)
 L6 意见层      意见工厂 | M10合规自检 | 质量校准 | 基准对照              (R14)
 L5 风控层      联立校验器 | 预期调节 | 回撤阶梯 | 批次纪律 | 冷静期      (R15)
 L4 分析层      S1六因子 | S3否决 | S4评分/三情景 | 市况分级 |            (R7-R13)
                持仓信号监测 | 论点卡证伪FSM | 组合级校验
 L3 编排层      四层状态机 | 调度器 | 触发器总线 | 冻结矩阵 | 回流        (R6)
 L2 规则层      规则库 | 参数解析 | 效力仲裁 | 裁决登记                   (R5)
 L1 数据层      适配器×11 | 质量控制 | 归一化 | 快照 | 交易日历           (R1-R4)
 L0 存证层      append-only 存储 | audit_chain | 重放服务                (R3,R18)
 ────────────────────────────────────────────────────────────
 旁路: LLM取证代理子系统 → 防幻觉校验链 → 证据对象入库(L1)              (R16)
```

依赖方向严格自上而下（L0/L1 为底），代理旁路只能通过防幻觉校验链写入 L1 的 evidence 表，不得触达 L2 以上任何判定接口（A1）。

### 2.2 部署视图

单机 Docker Compose 四容器（规格书 §2.3）：

| 容器 | 职责 | 关键点 |
|---|---|---|
| `app` | FastAPI：交互层 API、签认/裁决、报告渲染 | 无状态，可重启 |
| `db` | PostgreSQL 16 + 挂载 Parquet 冷层卷 | append-only 由触发器强制（§4.4） |
| `scheduler` | APScheduler（P2 起可换 Prefect）：日历任务 + 触发器总线消费者 | 心跳上报（R19.1）；崩溃恢复靠 trigger_event 持久化重放（R6.4） |
| `agent-runner` | LLM 代理执行器（Agent SDK） | 与判定进程物理隔离，只有 evidence 写入通道（A1）；用量计量（R19.5） |

启动前置自检（R1.1/R1.2）由 `app` 容器 entrypoint 执行；生产模式探测失败时进程仍启动但 `mode=degraded`，意见生成接口返回降级声明。

### 2.3 编排作用域（四层，R6.1）

- **系统级单例**：S0 参数化、S12 复盘、全局冻结标志、市况级别、预期调节覆盖参数。实现为 `system_state` 单行表 + 事件溯源。
- **行业级**：S1 每行业一评分记录；出闸事件广播终止该行业全部标的实例（R6.2）。
- **标的级**：S2-S11 每标的一状态机实例（`instrument.state` + 状态迁移守卫表驱动）。
- **组合级**：风控联立、回撤阶梯、基准对照、分桶、卖铲子占比——无独立状态机，实现为 S5/S7 放行守卫 + 日终计算任务。

## 3. 组件设计

### 3.1 数据层（L1，承载 R1-R4）

**适配器框架**。统一基类，每适配器实现探测/取数/限速三接口：

```python
class BaseAdapter(Protocol):
    def probe(self) -> ProbeResult            # 连通性+鉴权+权限覆盖率 (R1.1/R1.3)
    def fetch(self, req: FetchSpec) -> list[RawRecord] | Gap
    rate_limit: RateLimitPolicy               # 限速重试（指数退避）
```

11 个适配器按规格书 §3.1 清单实现（ADP-TUSHARE/AKSHARE/EDGAR/FMP/CONSENSUS/IBKR/FRED/CNINFO/INDEX/INDUSTRY/AGENT + D10 自建资产）。要点：

- **主备切换**（R1.4）：源角色（主/备/仲裁）是 `source_role` 配置表数据而非代码分支；FMP token 配置事件将 D2/D4 的主源角色改写为 FMP、EDGAR 改为备+仲裁，判定路径不改代码。
- **IBKR 断连**（R1.5）：适配器抛 `UpstreamDown` → 编排层将"行情依赖"标记的节点置 FROZEN，其余节点照常；重连事件触发缺失区间补拉任务。
- **HFIAA 分界**（R1.6）：EDGAR Form 4 采集器对 FPI 标的按 `filing_date >= 2026-03-18` 取数，之前区间写入"豁免期无数据"标注对象（非 Gap——该缺失是合法状态）。

**质量控制管道**。入库路径固定为四段：`RawRecord → 新鲜度打标(R2.1) → 双源仲裁(R2.2/R2.3) → 归一化(R2.4/R2.5) → evidence/gap 落库(R2.6)`。

- 双源仲裁数值字段依赖**字段字典**（`field_dict` 配置表：字段→保守方向→容差→消费场景），差异 >1% 按登记方向取值并写 `discrepancy_log`；分类/文本字段冲突直接产 Gap + 裁决队列条目，代码里没有"择一"分支（R2.3）。
- 归一化引擎实现为可组合的 `Normalizer` 管道（拆股/53 周财年/ADR 半年折算/终止经营剔除/一次性标记），每个变换记录 `(原值, 变换, 参数, 出处)` 到 evidence 的口径字段——六个实跑案例即 R20.3 的 fixture。
- 负净利现金转化率规则（R2.5）实现在归一化引擎出口的派生指标计算器中，规则参数挂框架 3.2-2 出处。

**快照管理器**（R3）。快照 = 元数据行（snapshot 表）+ 证据 ID 集合（不复制数据，靠 append-only 保证不可变）。月度快照在期次基准日收盘后由调度器切齐并置 `frozen=true`；此后任何补跑产物 `attempt` 挂下一快照版本。事件快照按需生成，引用当时生效的 `rule_version/param_version/生效裁决集`。重放服务：确定性节点从快照证据集重算并逐字段 diff（R3.3）；LLM 节点读档不重取（R3.4）。活数据白名单在数据访问层实现：只有 `SignalDetector` 与 `NavMonitor` 两个调用方标识可查询非快照数据，且其输出类型只能是 `TriggerEvent`（R3.5）。

**交易日历服务**（R4）。`exchange_calendars`（XSHG+XNYS）封装为 `CalendarService`，提供：交易日算术（N 交易日按标的市场）、账务日拼合（美东收盘日为账务日，A 股取同账务日最近收盘）、时间量词解析器（`Duration("30td", market)` / `Duration("48h", wall_clock)` / `Duration("90d", natural)`）——全系统禁止裸用 `timedelta` 表达业务时限（lint 规则）。

### 3.2 规则层（L2，承载 R5）

**规则库**。规则条目 = 数据（rule 表），不是代码：`{id, 框架出处, 类型(阈值/触发-动作/断言/流程守卫), 参数槽, 效力级, 保守方向, 版本}`。规则引擎是解释器：输入（规则 ID + 证据集 + 参数集）→ 输出（判定 + 引用三元组）。建库方式为**逐条文遍历**（R5.1）：框架 v2.0 每一条含量化/动作语义的条文对应至少一条规则条目，建库产出"框架条文 ↔ 规则条目"覆盖矩阵（R20 验收输入）。

**参数解析器**（R5.2）：取值链 `param_signed（签署值）→ 附录 E 默认值`；写路径上有方向校验器（每参数登记"更严方向"，判定线只升/仓位上限只降/现金下限只升），违反方向的修改请求直接拒绝；通过的修改产生新版本行 + 生效条件（无未决交易）。**预期调节/校准产生的临时覆盖参数**（R15.2/R14.6/R14.8）作为带有效期的 `param_override` 行存在，解析顺序：生效覆盖 → 签署值 → 默认值。

**效力仲裁器**（R5.3）：规则冲突静态检测（建库时）+ 运行时同事件多规则仲裁（红线 > 第六章 > 第三章 > 第四章，同级取严）；不可判则产出裁决请求并冻结扩权类判断。

**裁决登记**（R5.6）：ruling 表含条件化复核触发器字段（谓词 + 复核窗口），调度器每日扫描到期复核条件生成复核任务。

### 3.3 编排层（L3，承载 R6）

**标的级状态机**：表驱动（状态 × 事件 → 守卫 + 迁移 + 产物），守卫函数全部纯函数化以便单测。S2-S11 迁移表直接翻译规格书 §5.1（含 S4 定性维未签认挂起、S8 关联校验、S9 回执缺失冻结）。

**触发器总线**（R6.4/R6.5）：所有触发源（财报事件/价格触发/信号检测/缺口关闭/裁决完成/日历）统一写 `trigger_event` 表（持久化优先于消费）；消费者以事务领取 + 消费确认；**并发仲裁窗口 = 同一账务日收盘评估批次**，批内按 6.6 顺位规则条目排序，高位吸收低位并在被吸收事件上留 `absorbed_by`。日终对账任务重算"当日应触发集"（从检测器输入独立推导）与"已处理集" diff，差异告警（R19.1）。

**冻结矩阵**（R6.3）：`freeze_gate(action_class, flags)` 纯函数 + 冻结标志位事件溯源（每个标志的置位/清除都是事件）。动作分类字典（防守类/扩权类/中性）随规则库版本化。

**回流控制器**（R6.6/R6.7）：滞留标的登记 `stranded_since_period`；缺口关闭事件或下期扫描触发补跑；期次计数 ≥3 转淘汰。裁决完成事件清冻结 + 状态机重入 S3；重跑遇未决裁决 → 本期挂起，幂等键防止重复派发裁决请求。

**调度器**（R6.8）：日历任务清单直接配置化（cron 表达式 + 交易日历修正），逐项对应 FR-O-01。

### 3.4 分析层（L4，承载 R7-R13）

各引擎共同形态：`Engine.run(snapshot_id, scope) -> list[产物 | Gap]`，只读快照、产物带三元组引用。

- **S1 六因子**（R7）：每因子一个 `FactorScorer`（证据齐备检查 → 档位判定规则条目 → 0-5 档）；缺证据计 0 + Gap。入围判定含"近似口径分不得推过线"检查：若去掉 ≈ 标证据后总分 <21，产敏感性警报 + 待裁决（R7.3——裁决 A 的机制化）。
- **S3 否决审查器**（R9）：五项 × 四态。数值子项直连归一化引擎派生指标；取证子项派发代理任务并等待证据；输出 `veto_verdict`（命中路径含逐条件布尔向量，支撑 R20.2 的逐条件断言）。
- **S4 评分引擎**（R10）：量化维自动计分；定性维产"初评待签认"条目并挂起；三情景计算器从证据对象取假设输入，输出 `scenario_calc`（熊/基/牛隐含回报 + PEG/EV-S 交叉验证）；判定线比较用生效参数（含覆盖）。季度重打分跌档处置直接生成对应意见对象（出处=框架 3.4）。
- **市况分级器**（R11）：10 信号检测器注册表（每项：数据源适配器 + 阈值规则条目 + 检测频率），capex 下修为独立最高权重信号；级别判定 + 生效区间落 `market_regime`；级别变更事件驱动风控参数档切换与任务生成（狂热档→全持仓分批兑现评估任务）。未覆盖重大事件走 O-04 人工通道（R11.4）。
- **持仓信号监测器**（R12）：6.2×6 + 6.3×5 检测器常驻；命中→trigger_event；48h 倒计时为墙钟定时器（持久化，进程重启恢复）；复评二选一结论由 S11 状态机守卫强制（不给第三选项）；观察期状态置于 instrument 上，期内信号命中的处理路径短路直达清仓意见生成。
- **论点卡证伪 FSM**（R13）：thesis_card 状态机（草稿→签认→季度标记循环→失效）；起草器从 score_card 证据自动生成；⚠️ 连续计数与核心 ❌ 的动作映射为规则条目；"换故事续命"防御：新论点必须新建 thesis_card 且原卡先走失效动作（R13.5）。
- **组合级校验计算器**：卖铲子占比（instrument 环节分类聚合）、持仓只数、分桶、±3pp 带宽漂移监测，输出供 §3.6 联立。

### 3.5 意见层（L6，承载 R14）

**意见工厂**：七类意见各一构造器，输入=触发上下文+证据三元组，Pydantic 模型十项字段全 required（构造失败即异常，R14.1）；编号发号器 `#YYYY-MM-NNN` 月内单调；有效期计算依赖 CalendarService + 财报日历（R14.2）。

**M10 合规自检器**（R14.3）：十项检查实现为独立 `Check` 函数管道，其中"确定性收益语言"为版本化词表匹配 + LLM 复核双层（词表为准，LLM 只能加严）；"证据链断链"检查即验证三元组引用完整性。任一不过→修正重试一次→仍不过输出"无法合规输出"对象（也是七类之外的系统声明，不带投资语义）。

**质量校准器**（R14.5/R14.6/R14.8）：90 天回看任务产出 `opinion_quality` 行；季度校准任务计算连败/连胜序列，触发判定线与现金档覆盖参数（走 §3.2 param_override 通道，自动解除条件挂调度器）。

### 3.6 风控层（L5，承载 R15）

**联立校验器**：全部限额实现为约束列表（每条挂规则条目），S5/S7 调用 `validate_all(portfolio_state, proposal) -> list[Violation]`——全过才放行，违反项逐条报告（不是遇错即停，用户需要完整违规清单）。红线两条（单票 ≤25%、杠杆=0）额外存在于断言层：即使规则库被误改，断言层仍拦截（防御纵深）。

**预期调节校验器**（R15.2）：滚动 12 个月收益计算依赖日终净值序列；触发时产 6 个月期 param_override。

**回撤阶梯**（R15.3）：高水位 = `max(历史日终净值)` 物化视图；三档触发分别产出冻结事件/降权益意见/防守底仓意见+停手期状态。停手期实现为全局冻结标志的一种，天然受 A5 短路保护。

**批次纪律跟踪器**（R15.4）：每个建仓/降回/兑现计划生成批次表，逐日核对回执进度，偏离产警报。

**冷静期与次数预算**（R15.5/R15.6）：滚动 24h 加仓累计用 decision_record 时间窗聚合（拆单在聚合口径下无法绕过，R20.5 有专门用例）；月/年计数器区分主动交易与框架强制动作（动作来源字段）。

### 3.7 LLM 取证代理子系统（旁路，承载 R16）

**任务管理器**：七类任务模板（版本化，模板即 prompt + 输出 schema + 勾稽规则集引用）；自然键幂等（R16.4）；attempt 链与最新有效指针。

**防幻觉校验链**（R16.2/R16.3）：三段流水线——
1. **来源回溯**：按证据的 source URL/归档快照重取原文，数值 ±容差匹配；仅元数据非空不算通过（机械谓词）。
2. **勾稽**：规则库内可枚举清单（季度加总 vs 年度、NI÷EPS vs 加权股数 ±2%、资产负债表勾稽…），每条带适用前提开关与容差。
3. **标签完整性**：新鲜度/口径必填校验。

任一失败 → `置信=UNVERIFIED`（由校验器置位，唯一写入方）→ 自动 Gap → 一次补取证 attempt → 仍失败按 A2 降级/滞留；勾稽矛盾单独路由裁决队列。

**模型分级**：按规格书 FR-A-04 双档（尽调级/抽取级），任务模板声明所需档位；用量计量入成本面板（R19.5）。

### 3.8 交互层（L7，承载 R17）

签认队列/裁决队列为 FastAPI + 服务端渲染（P0-P2 用 Streamlit 面板，P3 迁 Next.js）；一切队列动作写 signoff/ruling 表。通知服务：通道抽象（IM webhook/短信 webhook），防守类警报走强送达路径（发送→送达确认→超时升级重发），扩权类进日摘要（R17.3）。驳回率统计进复盘议程（R17.2）。S0 不适用情形硬拒绝在参数签署 API 层实现（R17.4）。

### 3.9 存证层（L0，承载 R18）

append-only 由 PostgreSQL 触发器强制：★ 表禁 UPDATE/DELETE（更正=新行 + superseded_by 指针）。audit_chain：每日批任务对当日新增对象计算链式哈希（前日链头 + 当日对象哈希 Merkle 根）；恢复演练脚本执行链校验 + 抽一历史判定重放 diff（R18.2）。一跳回溯查询（R18.4）实现为预建视图 `opinion_trace`。

## 4. 数据模型

PostgreSQL 主存 + Parquet 冷层（行情 K 线、原文快照）。表清单以规格书 §3.3 为准（20 表），本节只补设计决策：

1. **键与外键**：evidence/gap/opinion 等 ★ 表主键为 ULID（时间有序）；判定产物表（industry_score/veto_verdict/score_card/scenario_calc）统一携带 `(rule_ids[], snapshot_id, evidence_ids[])` 三列，NOT NULL + 引用校验触发器（A4）。
2. **快照成员关系**：`snapshot_member(snapshot_id, evidence_id)` 关联表而非数组列——证据集可达数万级，需索引反查"证据属于哪些快照"。
3. **append-only 强制**：★ 表挂 `BEFORE UPDATE OR DELETE → RAISE` 触发器；应用层 ORM 也不生成 update 方法（双保险）。
4. **状态字段事件溯源**：instrument.state、冻结标志、市况级别均可由事件流重建，物化当前值仅为查询加速；重放校验时以事件流为准。
5. **配置即数据**：field_dict（字段字典）、source_role（主备角色）、动作分类字典、信号检测器注册表、日历任务清单均为版本化配置表，纳入快照范围（☆），保证重放取到当时配置。
6. **Parquet 冷层**：日线行情按 `market/symbol/year` 分区；原文（PDF/HTML 快照）按 `source/date` 归档，evidence 行存指针 + 内容哈希。

## 5. 关键流程

### 5.1 月度管道（S1→S5）

```
调度器(月度) → 快照管理器: 切齐月度快照(frozen)
→ S1: 六因子×行业 → industry_score → 入围清单（近似分敏感性检查）
→ S2: 三来源并集 → 流动性过滤 → 颠覆名单核对 → A/B/C 分组
→ S3(A组): 数值子项(归一化指标) ∥ 取证子项(代理任务→防幻觉链→证据)
   → 四态判定 {淘汰|滞留|裁决冻结|通过}
→ S4(通过者): 量化维计分 ∥ 定性维初评→签认队列(挂起点①)
   → 签认后: 总分+三情景+熊市拦截
→ S5: 风控联立(§3.6) + 市况档检查 + 清单≤上限 → 意见工厂 → M10自检 → 推荐清单
```

挂起点（签认/裁决）不阻塞其他标的的管道推进（每标的独立状态机实例）。

### 5.2 事件触发复评（S10→S11→S8）

```
检测器(活数据白名单) → trigger_event(持久化) → 账务日批次仲裁(6.6顺位)
→ 事件快照生成 → S11 复评(引用事件快照)
→ 6.2 路径: 48h倒计时 → 二选一 {确认→清仓意见 | 不能确认→减半意见+观察期}
→ 论点卡路径: 假设标记签认 → 证伪FSM → {清仓|减半|继续}
→ 动作 → S8 决策关联校验 → (用户场外执行) → S9 回执
→ 日终: 应触发vs已处理对账
```

### 5.3 签认与裁决闭环

```
系统产出(初评/论点卡草案/参数变更/复盘结论) → 签认队列 → 用户{签认|修改(方向校验)|驳回(记理由)}
边缘判定/口径冲突/勾稽矛盾 → 裁决队列(争点+正反证据+缺省处置+复核条件)
  → 未决期间: 标的冻结扩权类, 缺省处置维持运行, 不重复派发
  → 裁决完成事件 → 清冻结 → 重入S3重判 → 条件化复核挂调度器
```

### 5.4 滞留回流

```
S3证据不足 → 滞留态(stranded_since_period=N)
→ {缺口关闭事件 | 下期扫描} → 补取证重跑(新attempt, 入下一快照)
→ 期次计数: 第N+3期仍滞留 → 转淘汰留痕
```

## 6. 错误处理与降级策略

| 故障类 | 处理 | 需求 |
|---|---|---|
| 上游源不可达 | 适配器重试(指数退避)→ 备源 → 仍失败产 Gap + 降级动作；生产核心源失败拒绝意见模式 | R1.2/R2.6 |
| IBKR 断连 | 行情依赖节点冻结，其余照常；重连补拉 | R1.5 |
| 双源数值分歧 | 保守方向取值+分歧记录；分类字段→裁决队列 | R2.2/R2.3 |
| 代理幻觉/取证失败 | UNVERIFIED→Gap→一次重试→降级/滞留；勾稽矛盾→裁决 | R16.3 |
| 调度器崩溃 | trigger_event 持久化，重启后重放未消费事件；日终对账兜底 | R6.4 |
| 48h 复评逾期 | 标的冻结（防守类除外）+ 强送达升级 | R12.2/R17.3 |
| 规则冲突不可仲裁 | 冻结扩权类 + 裁决请求 | R5.3 |
| 意见自检不过 | 修正一次→"无法合规输出"声明 | R14.3 |
| 数据库损毁 | 每日备份 RPO≤24h；恢复演练含链校验+重放 | R19.3/R18.2 |

通用原则：**一切降级显式留痕**（Gap 对象/降级声明/G 级标注），静默降级视为缺陷；防守类路径的故障处理永远选"更保守动作可执行"的分支（A5）。

## 7. 测试策略

分五层，验收锚点为 R20：

1. **单元**：守卫纯函数、归一化变换、时间量词解析、约束校验器逐条——阈值从规则库注入，测试用例挂规则条目 ID（覆盖矩阵三向映射：条文↔规则↔用例）。
2. **金标准回归**（R20.1/R20.2/R20.3）：`fixtures/golden/` 为 P0 第一工作项——S1/S2/S3 第 1 期报告的输入证据回填为机器可读 fixture（FactSet 型一次性来源固化为证据对象）。断言集：S1 复现 23/21/17/17/17/15/8/6（裁决 A 前后两态，锁定裁决集）；S2 复现 A 组 24 只+排除清单+B/C 组；S3 复现 10/3/3/8 且 MPWR/SNPS/AEHR 命中路径逐条件断言；归一化六案例。
3. **防幻觉对抗**（R20.4）：注入编造数字/伪来源/勾稽矛盾的代理输出样本库，断言 UNVERIFIED 拦截率 100%（按机械谓词）。
4. **场景断言**（R20.5）：冻结期止损放行（A5）、观察期内信号直清仓、拆单避冷静期被拒、红线绕过被拒、四种未签认/未裁决态下 S5-S8 拒绝——每场景一集成测试，构造完整状态后走真实编排路径。
5. **重放与灾备**：同快照重放逐字段一致（R3.3）；恢复演练脚本（链校验+历史判定重放）纳入季度 CI 任务（R19.3）。

CI 门槛：金标准回归 + 场景断言 + 防幻觉对抗为合并阻断项；红线断言层代码变更需双人复核规则（仓库保护）。
